# 大文件拆分计划

## 目标

减少大文件职责混杂，让代码更健壮、低耦合、高内聚，同时保持现有行为不变。

## 原则

- 先搬低风险职责，不改业务结果。
- 只拆已经清楚的边界，不为了拆而拆。
- 每一步都能用测试证明行为没变。
- 失败直接暴露，不新增静默兜底。

## 开发计划

1. 拆 `app.py` 的 Web 运行时小工具。
   - 验证：新增工具函数测试，现有 Web 历史测试通过。

2. 拆 `app.py` 的大段主题 CSS。
   - 验证：`app.py` 语法检查通过，主题渲染入口仍由 Streamlit 调用。

3. 评估下一步拆 `typeset_html.py` 或 `core/extractor.py`。
   - 验证：本轮不做高风险渲染规则搬迁，只记录下一步边界。

4. 跑相关测试和全量测试。
   - 验证：测试全部通过。
