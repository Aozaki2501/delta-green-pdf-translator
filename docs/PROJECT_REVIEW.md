# 项目风险、优化与前端重构记录

更新时间：2026-07-10

## 当前结论

项目已经具备可用的 PDF、Markdown、Word 翻译流水线，断点续跑、术语匹配、质量报告和 TRPG 规则检查是主要优势。当前重点不是继续增加零散功能，而是先保证译文完整、术语一致、状态可信，再重构前端工作流。

## 已确认风险

### 先处理

1. 模型返回因长度截断时，程序没有检查 `finish_reason`，非空的部分译文可能被缓存为成功。
2. Markdown 和 Word 命令行仍默认使用即将停用的 `deepseek-chat`。
3. 费用使用固定单价计算，却允许任意模型和兼容接口，界面显示的人民币费用不可信。
4. 默认术语表有 6 组大小写不敏感冲突，包括 `Agent`、`ifrit`、`unnatural`，当前会静默选取其中一个译名。
5. 进度 JSON 损坏时会静默从头开始，后续保存可能覆盖原文件，造成译文丢失和重复付费。
6. 进度指纹没有记录模糊匹配、Word 页眉翻译等会改变译文的设置，切换设置后可能复用旧译文。
7. README 列出的备团清单、模组结构和时间线尚未接入主流程；Word 校对包目前也没有使用时间线数据。

### 随后处理

1. 高并发时，同一批 Markdown/Word 文本共享同一份前文，不能保证每段都获得真正的相邻上下文。
2. PDF 串行和并行模式使用不同的上下文策略，结果可能随并发设置变化。
3. 质量检查主要依赖字符比例和少量规则符号，可能漏过中度截断、段落遗漏、线索错位和数值改写。
4. `uploads/` 和 `output/` 没有清理入口或保存期限；审计文件还会记录本机绝对路径。
5. 用户可填写任意兼容接口，原文和密钥会发送给该接口；远程非 HTTPS 地址尤其危险。
6. 仓库缺少 CI、依赖锁文件和 LICENSE；现有测试以单元和合成数据为主，缺少真实模组端到端回归。
7. `app.py`、`webui/theme.py`、PDF 提取和排版文件体积较大，界面与业务流程继续堆叠会增加维护成本。

## TRPG 翻译优化方向

### 译文完整性

1. 检查模型停止原因；发生长度截断时直接失败并拆分重译。
2. 对标题、表格、卡片、数据块和 `[BLOCK]` 标记做数量与顺序校验。
3. 对百分比、骰子、SAN 损失、HP、WP、护甲、伤害、致死率、射程和技能值做源译文逐项对照。
4. PDF 也采用块级完整性清单，避免只确认“这一页有译文”。

### 长篇一致性

1. 术语表升级为实体表，记录标准译名、别名、类别、性别、组织关系、语境、证据页和备注。
2. 同一英文表面词出现多个译名时直接报错，不再静默选择。
3. 先抽取全书高频人物、地点、组织和行动代号，再开始正文翻译。
4. 以章节或场景为并行单位；章节内部按顺序翻译，并维护人物、地点和语气摘要。
5. 术语变化后只重翻受影响的页或块。

### 真实质量验证

1. 建立小型真实模组回归集，覆盖双栏、跨页段落、数据块、玩家手册、线索卡、时间线、表格和异常字体。
2. 每次改动检查文本完整性、规则数字、阅读顺序和输出版式，不要求译文逐字相同。
3. 扫描件先做明确预检；OCR 通过外部适配器接入，不在本项目内重造完整 OCR 引擎。

## 前端重构方向

### 产品定位

界面应定位为“TRPG 翻译与校对工作台”，不是宣传页，也不是模拟终端。Delta Green 氛围可以保留为颜色和少量文案，但不能干扰上传、配置、校对和重翻。

### 推荐信息结构

1. **新建任务**：上传文件 → 选择范围和输出 → 确认术语 → 提取预检 → 开始翻译。
2. **执行中**：只显示总进度、当前步骤、失败项、预计时间和暂停/继续操作。
3. **校对**：风险列表在左，原文与译文并排，右侧显示术语和规则数值；支持勾选后重翻。
4. **档案库**：按任务展示状态、时间、源文件、输出、失败页和离线重导出。

### 视觉原则

1. 使用一个稳定设计系统，提供浅色/深色主题，不再维护两套不同结构的“终端模式”和“办公模式”。
2. 去掉启动遮罩、大型英雄区、雷达和重复状态卡；首屏三秒内应看到上传区和主操作。
3. 采用中性灰背景、白色内容区、深绿色主色；红色只表示失败，琥珀色表示警告。
4. 圆角控制在 6–8px，减少卡片套卡片；用分组标题和留白表达层级。
5. 正文字号保持 14–16px，参数标签清楚，避免密集面板中的大标题。
6. 动画只用于进度和状态变化；完整支持低动效、键盘焦点和足够的文字对比度。

### 交互原则

1. 默认只展示必要设置，高级设置按输入类型和输出格式动态出现。
2. API 地址、模型和密钥放入独立的“连接设置”，新建任务只显示当前连接摘要。
3. 在执行前提供一张最终确认摘要：页数、输出、术语表、模型、并发和预计调用量。
4. 费用计算修复前不显示金额，只显示 Token 和 API 调用次数。
5. 错误信息必须说明下一步，例如“重新提取”“只重试失败页”或“离线重导出”。

### 代码拆分建议

1. `app.py` 只保留路由和会话状态。
2. 新建 `webui/pages/`，分别承载新建任务、执行、校对和档案库。
3. 新建可复用组件：任务摘要、步骤条、连接状态、术语表、质量问题列表、原译文对照、输出文件列表。
4. 主题文件只保留变量、基础控件和响应式规则，删除重复的两套大段 CSS。
5. 重构时先保持业务行为不变，再逐页迁移；每个页面完成后做桌面和窄屏截图检查。

## 验证基线

- 578 个测试通过。
- 语法和环境检查通过。
- 75 个已安装依赖兼容。
- 当前缺少真实 API、真实 PDF 和浏览器端到端回归，这部分应在重构前补最小基线。
