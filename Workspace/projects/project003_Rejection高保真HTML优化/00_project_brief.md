# 项目简报

## 目标

以 Rejection 前 25 页现有高保真 HTML 为真实回归样本，修复浏览器实测溢出，并收口高保真与普通文档链路的内容处理、缓存、断点、重试、质量检查和成品发布问题。

## 范围

- 对照英文原 PDF 与当前第一版中文 HTML；《融合》只作人工排版风格参考。
- 修复通用代码，不写页码专用补丁。
- 优先修改 `core/`、`exporters/` 和对应测试。
- 保留当前翻译结果，不整本重翻，不覆盖现有成品。
- 不处理 OCR，不修改人工汉化 PDF。

## 输入

- 英文原件：64 页 Rejection PDF。
- 当前产物：前 25 页 `_typeset.html`、页面结构、内容、译文进度和布局报告。
- Rejection 没有人工汉化版；当前 HTML 是唯一中文版本。
- 人工排版参考：《绿色三角洲-融合》20 页。

## 输出

- 通过浏览器严格验收的 Rejection 前 25 页候选 HTML。
- 原文、当前 HTML 与人工排版参考的对照截图和检查记录。
- 高保真缓存、断点、重试、质量检查、原子发布的通用修复。
- 回归测试和当前状态记录。

## 完成标准

1. 前 25 页 Chromium 布局问题为 0。
2. 每个可翻译块在 HTML 中有且只有一个明确渲染归属。
3. 字体真实加载，正文、标题、表格、卡片无裁切、重叠或缺字。
4. 页码范围、排版配置、模型和提示词变化时不复用不兼容缓存。
5. 高保真进度损坏时保留备份并显式报告。
6. 同一失败不经过多层重复重试。
7. 未通过验收的候选 HTML 不覆盖正式成品。
8. 与改动范围匹配的测试和全量测试全部通过。

## 验证方式

- PyMuPDF 渲染英文原件和两份人工汉化参考。
- Playwright 渲染当前与候选 HTML，收集 DOM、字体和布局数据。
- 代表页逐页截图对照，最后检查全部 25 页。
- 自动测试覆盖状态身份、损坏断点、重试次数、块覆盖和原子发布。
